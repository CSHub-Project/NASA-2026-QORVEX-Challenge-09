# Fyrora submission kit

This directory is the single handoff point for the NASA Space Apps project page, live pitch, demo recording, judging review, and technical diagram.

## Use order

1. Paste the reviewed copy from `project-page.en.md` into the official project page.
2. Rehearse `demo-script.en.md`; use `demo-script.fa.md` for team preparation.
3. Keep `architecture.md` open for technical questions.
4. Have a second team member score the project with `judge-scorecard.md`.
5. Complete every blocking item in `final-checklist.fa.md` before submission.
6. Use `europe-one-pager.en.md` for European partner discovery; it states the pilot and commercial hypotheses without implying customers or revenue.
7. Use `form-field-map.md` while completing the live Project tab.
8. Follow `release-procedure.md` only after the demo, video, and project page are final.
9. Use `resume-entry.en.md` after reconciling the final team contribution record.
10. Follow `deployment.md` for the private-to-public release sequence.

Current quantitative claims come from committed four-region, 2021–2024,
full-swath, and frozen EFFIS outcome tables linked from `README.md`. The EFFIS
overall gate failed and must remain visible in the project page and pitch. Keep
the pre-hackathon eligibility question visible until the registered event
confirms how prior work may be used. Do not replace measurements with marketing
claims unless the underlying tables are updated and the tests still pass.
